# WebGPU Production Snapshots

The canned production captures generated by `npm run demo:webgpu:examples` provide deterministic references for the mocked Quest/Vision Pro rendering path. Each run writes structured JSON under `DOCS/examples/` so you can diff your live output against the baseline values described below.

## Regenerating the snapshots

```bash
npm run demo:webgpu:examples
```

This command will emit:

- `webgpu-pipeline-production.json`
- `webgpu-xr-loop-production.json`

Both files include only plain numbers and string labels, making them easy to diff in CI or during local experiments.

### Visual gallery

For a UI-first readout, refresh the captures and serve the static gallery:

```bash
npm run demo:webgpu:examples
npm run demo:webgpu:serve
```

Open `http://localhost:4173` and you will see the pipeline and XR frames rendered in a glassmorphic dashboard that mirrors the live renderer’s aesthetic while surfacing key metrics from both JSON files.

## Glassmorphic pipeline sample (`webgpu-pipeline-production.json`)

The pipeline snapshot captures the triple-buffered uniform uploads and render pass orchestration for two sequential frames rendered at 1280×720.

### Layer textures

Four render targets are created for the two-layer glassmorphic stack plus the paired horizontal/vertical blur textures, all in `rgba16float`:

- `glassmorphic-layer-0`
- `glassmorphic-layer-1`
- `glassmorphic-blur-h-0`
- `glassmorphic-blur-v-0`
- `glassmorphic-blur-h-1`
- `glassmorphic-blur-v-1`

### Frame 1 highlights

- Translation snapshot: `(1, 1.5, -2)` with a smoothed pose weight of `0.85` after the first update.
- Quaternion components produce a `25°` yaw (`0.4363` radians), yielding the rotation matrix `[0.9063, 0, 0.4226; 0, 1, 0; -0.4226, 0, 0.9063]`.
- Audio bins normalize the `[0, 64, 192, 255]` mock buffer to `[0, 0.251, 0.7529, 1]` in the first four slots.
- Render passes execute cached bundles in the order: two layer draws → horizontal blur → vertical blur → composite to `final-target-view`.

### Frame 2 highlights

- Translation advances to `(1.2, 1.6, -1.8)` and the pipeline reports the smoothed velocity `(0.35, 0.016, 0.016)` with a magnitude of `18.75`.
- The quaternion corresponds to a `60°` yaw (matrix `[0.5, 0, 0.866; 0, 1, 0; -0.866, 0, 0.5]`).
- Audio normalization tracks the `[16, 128, 220, 255]` input as `[0.0627, 0.502, 0.8627, 1]`.
- The render pass list mirrors Frame 1, confirming render-bundle reuse.

## XR frame loop sample (`webgpu-xr-loop-production.json`)

The XR snapshot traces the mock session binding, pose smoothing, and submitted command buffers for two simulated viewer poses.

- Session startup records an `updateRenderState` call that installs the `projection-layer`.
- Pose uniforms show the smoothed quaternion progression from a `5°` yaw (`0.0436` radians) to `25°`, with translations fixed at `(0, 1.6, -0.2)`.
- Each frame submits six passes (`layer 0`, blur horizontal, blur vertical, layer 1, composite, plus an implicit depth target), packaged inside `webgpu-xr-frame::commands`.
- Audio uniforms carry the `[0, 128, 64, 255]` analyser payload normalized once per frame.

Use these metrics as ground truth when validating future pipeline tweaks, shader changes, or integration code that consumes the pose uniform payloads.
